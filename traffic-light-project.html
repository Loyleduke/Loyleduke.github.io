Traffic Light System

Project Overview

I built a sequence state traffic light in order to learn the basics of ladder logic and how to think about programming state machines. I used an esp32 and some smaller electronic components with Openplc(Able to translate ladder logic to C/C++ and flash to microcontroller) to mimic a real plc and the traffic light hardware. Although the project is quite basic I definitley learned a lot from it.

See It in Action

System Logic

Once the programme is uploaded, the traffic light automatically begins its normal operating sequence, cycling through green, amber, and red states. The hardware configuration uses sinking NPN inputs and sourcing PNP outputs, with Set/Reset (latching) logic used to control and maintain the different system states.

During normal operation, the lights continuously progress through the standard sequence. When the pedestrian crossing button is pressed, a crossing request is registered and latched by the programme. The current traffic-light sequence is not interrupted; instead, the system waits until the lights naturally reach the next red phase.

When the next red phase is reached, the latched crossing request triggers the pedestrian crossing state, causing the crossing signal to flash while the traffic lights remain at red. Once the crossing sequence is complete, the crossing latch is reset and the system returns to its normal sequence, restarting from the green state.

Problems & Solutions

Floating pin issue

The first issue encountered was false triggering of the pedestrian crossing button. The initial setup used sourcing inputs at only 3.3 V, making the input susceptible to electrical interference. Static and electrical noise from other devices in the room was occasionally enough to trigger the input without the button being pressed. To resolve this, I changed the configuration to sinking (NPN) inputs, providing a more stable reference and significantly reducing false triggers.

resistor issue

Another issue was that the green LED appeared dimmer than the red LED. This was caused by the different forward voltages of the LEDs, meaning the same resistor value did not produce the same current through each colour.

Green = (3.3V − 2.2V) ÷ 0.01A

Green = 110 Ω

Red = (3.3V − 1.8V) ÷ 0.01A

Red = 150 Ω

To achieve the same current i had to adjust the resistor i was using.
