Analog weight sorter

Project Overview

I built a weight sorting system with a HMI in order to learn about analog I/O and how to programme state machines. I used an esp32 and some smaller electronic components with Openplc(Able to translate ladder logic to C/C++ and flash to microcontroller) to mimic a real plc.I used Ignition and a modbus TCP connection to import tags I needed.

See It in Action

System Logic

The conveyor uses an integer state register to control the weighing process. The main states are IDLE, RUNNING, STOPPED, WEIGHING, ACCEPT, and REJECT, with defined transitions between each state.

The system starts in IDLE and moves to RUNNING when the start button is pressed. When a part reaches the sensor, the conveyor stops and the system enters STOPPED. A short settling timer then allows the part to stabilise before moving to WEIGHING.

In the WEIGHING state, the current weight is stored in a variable and compared against the acceptance range. A weight between 40–70 kg results in ACCEPT, while weights below 40 kg or above 70 kg result in REJECT. The system then returns to the normal sequence ready for the next part. The dashboard counts can also be cleared using the Reset Count button.

Problems & Solutions

Address Mapping

One of the first challenges was understanding how to correctly map the OpenPLC variables to Ignition using Modbus addressing. I initially struggled to determine the correct addresses, but after researching the OpenPLC Modbus addressing for microcontrollers, I was able to establish the correct mappings.I also discovered that the Unit ID in Ignition must match the slave ID configured in OpenPLC. Initially, these were set differently, preventing the two systems from communicating correctly. Once the Unit ID and slave ID were matched, the Modbus connection and variable mapping worked as expected.

Analog scaling

Another issue was getting the analog input to display the correct weight. The ESP32 uses a 12-bit ADC, giving a raw range of 0–4095, while OpenPLC was scaling the input to a 16-bit range of 0–65,535. This meant the raw values could not be used directly for the weight calculation. I had to account for the difference in resolution and recalculate the scaling range so that the value received by OpenPLC matched the actual analog input. This resulted in a more accurate weight reading across the conveyor's operating range.
